# 农村智慧社区系统

> 网格化社区管理 · 人口房屋台账审核 · 农产品交易全流程 · 党建活动报名签到 · 论坛互动与内容审核 · 民生服务协同 · 消息通知 · ECharts 数据分析

村里的通知靠微信群、宅基地信息靠手写台账、农产品只能在赶集日卖——这些场景凑在一起，其实就是一个很实在的课题：**基层治理里那些"纸面流程"，能不能搬到线上，并且留得下记录、审得了内容、看得见数据。**

这套系统把网格化治理、人口房屋台账、村务公开、党建活动、农产品交易、社区论坛和民生服务这些场景做成了一个整体：村民提交的信息要走审核，审核结果会推消息，每一步关键操作都写日志，管理端用 ECharts 看全局。做毕设讲答辩时，"多角色审核流转 + 事件留痕"这套叙事比单纯的管理系统有内容得多。

---

## 一、项目简介

农村智慧社区系统采用前后端分离的 B/S 架构，由面向村民和户主的前台门户、面向管理员的 Web 管理端，以及 Spring Boot 服务端组成。系统围绕网格化治理、人口与房屋信息、村务公开、党建活动、农产品交易、社区论坛和民生服务等场景，把社区服务串成一条从提交、审核、通知到统计的完整链路，并通过消息通知、数据看板和操作日志支撑基层治理与日常运营。

## 五、核心实现说明

### 5.1 多角色注册审核、JWT 鉴权与权限控制

系统定义管理员、户主和村民三类角色。户主与村民注册时会校验账号、手机号和邮箱的唯一性，密码经 MD5 处理后以待审核状态保存；管理员审核通过后，用户才可获得登录令牌。前端基于角色进行路由访问控制，服务端通过拦截器解析请求头中的 JWT，并将当前用户信息写入上下文，供后续业务校验和数据范围处理使用。

```
提交注册信息 → 唯一性校验与待审核保存 → 管理员审核
  → 签发 JWT Token → 前端路由守卫 → 服务端拦截器解析当前用户
```

### 5.2 网格化治理、人口房屋台账与事件处理

网格化模块维护网格名称、编码、边界、中心坐标和负责人等基础信息，并关联房屋、人口与社区事件。村民可提交人口和房屋资料，管理员按照待审核、审核通过、审核拒绝等状态完成校验，同时通过站内消息反馈处理结果。社区事件支持分类、位置和状态维护，管理员可结合事件热力图查看事件空间分布与处理情况。

```
网格划分 → 关联房屋与人口 → 村民信息上报 → 管理员审核
  → 状态通知 → 事件登记与处置 → 地图热力展示
```

| 业务场景 | 系统处理结果 |
| :--- | :--- |
| 人口信息上报 | 记录人员基本信息、户籍关联、房屋与网格归属；审核完成后向上报人发送结果通知 |
| 房屋信息上报 | 维护房屋编号、地址、面积、类型、户主和网格信息，并通过审核状态控制资料有效性 |
| 社区事件处置 | 按待处理、处理中、已解决、已结案和已驳回等状态跟踪事件，保留事件类型、内容与地理位置 |

### 5.3 农产品发布、审核与订单交易全流程

农产品模块覆盖产品分类、发布审核、集市浏览和订单履约。村民发布产品后由管理员审核，审核通过且上架的产品可进入交易。创建订单时，服务端校验产品存在性、上架状态和可用库存，并由后端计算订单总价及生成订单编号；下单即预扣库存，支付后增加销量。订单取消会按原订单状态恢复库存，并在已支付场景同步回退销量；待付款订单超过 30 分钟会由定时任务自动取消。

```
产品发布 → 管理员审核 → 集市浏览 → 创建订单并预扣库存
  → 支付 → 卖家发货 → 买家确认收货 → 订单完成
```

| 订单节点 | 系统处理结果 |
| :--- | :--- |
| 创建订单 | 校验库存与上架状态，按单价和数量计算总价，生成订单编号并将状态置为待付款 |
| 支付与发货 | 支付成功后订单流转为待发货并增加销量；卖家发货后流转为待收货 |
| 取消与超时 | 待付款或待发货订单可取消，系统恢复库存；已支付订单同步回退销量，超时未支付订单自动执行相同回退逻辑 |

### 5.4 党建活动、报名与签到管理

管理员可发布党建活动，配置活动地点、报名截止时间、起止时间和人数上限。系统定时判断活动时间，使活动在报名中、未开始、进行中和已结束之间自动流转，管理员可在活动结束前取消活动。村民报名时会校验活动状态、报名截止时间、是否重复报名及人数限制；活动进行中可办理签到，也支持在未签到状态取消报名或撤销签到。

```
发布活动 → 自动进入报名阶段 → 村民报名 → 截止报名
  → 活动进行中签到 → 活动结束 → 查看报名与签到记录
```

### 5.5 社区论坛互动与内容审核

论坛按板块组织帖子内容，村民可发布、编辑和查看帖子，并进行评论、点赞与收藏。新发布的帖子进入待审核状态，管理员使用独立的通过或驳回操作处理内容；审核记录保存审核人、审核时间和驳回原因。审核完成后，系统向发布者写入关联帖子记录的站内消息，使用户能够在消息中心查看审核结果。

### 5.6 村务公开与民生服务协同

系统提供村务公开、通知公告和便民服务信息发布入口，方便居民获取社区资讯与服务资源。针对日常诉求，村民可提交在线报修、咨询服务和意见反馈；管理端按业务状态处理事项、填写答复或处理结果，并向提交用户发送消息通知。服务模块将公开信息与可追踪的诉求处理记录结合，形成从居民提交到管理员响应的服务链路。

| 服务模块 | 页面与业务能力 |
| :--- | :--- |
| 村务与公告 | 按分类发布和浏览村务公开信息，维护系统通知的发布、置顶与展示状态 |
| 便民服务 | 维护医疗、教育和便民等服务信息，展示服务联系人、地址与内容 |
| 报修、咨询与反馈 | 提交问题和诉求，管理端处理报修状态、回复咨询与反馈，并将结果推送至消息中心 |

### 5.7 消息通知与社区数据可视化

消息模块统一保存接收用户、标题、内容、消息类型、关联业务编号和阅读状态，承接人口房屋审核、论坛帖子审核、咨询回复和反馈回复等业务提醒。管理端基于 ECharts 展示系统概览、人口、农产品、民生服务和论坛统计数据，其中论坛统计结合词云呈现内容关键词；事件热力图以地图方式展示社区事件分布，为社区治理提供数据参考。

### 5.8 操作日志与业务追溯

管理端的关键业务操作通过 `@OperLog` 注解接入 AOP 切面。操作成功后，系统从当前用户上下文与请求信息中提取操作人、操作类型、所属模块、操作描述、客户端 IP、浏览器标识和操作时间，写入操作日志。日志记录失败不会中断主业务流程，管理员可在后台按条件查询日志，为审核、维护与服务处理提供追溯依据。
